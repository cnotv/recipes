## Shared agreements

These rules come from `cnotv/agent-base` and apply to every repository that carries this
block. The block is managed: edit it in agent-base, never here, and let the dashboard's
"Sync" open the pull request that updates it. What is specific to this repository lives
outside the block, under **Project facts** and the repository's own sections.

### How work starts

Run the `start` skill first. It classifies the request and names the workflow to follow.
Every workflow that changes the repository opens an issue, a branch and a draft pull request,
in that order, before any code:

1. **The issue.** One that already exists is read, comments included; otherwise it is written
   from the request. If intent, scope or expected behaviour is unclear, ask one focused
   question covering everything missing, wait, and write it from the answer.
2. **The branch**, off main, named `<type>/<issue-number>-<description>`. A fresh branch every
   time, never the current one, never reused.
3. **The draft pull request**, opened at the first commit rather than the last, carrying
   `Closes #<issue-number>` and kept current as the work moves.

`start-issue` covers the first two steps and `open-pr` the third. Tests come first, except for
an exploratory prototype, which still owes them before the pull request is marked ready.

### Working agreements

- **Ask before assuming.** If intent, scope or expected behaviour is unclear, ask one focused
  question covering everything missing, and wait.
- **Give an opinion.** When asked what you think, say what you would do and why. Never stop at
  "it depends".
- **Write it once, at the length it earns.** Prose that repeats the diff or restates something
  already written is noise. Each kind of writing has one home, listed under Project facts.
- **Never loosen a lint rule to pass it**, never use `eslint-disable` in any form, and never
  `--no-verify`. If a hook or a rule fails, it is usually right.
- **No emoji** anywhere — code, comments, UI text, commit messages, documentation — unless
  explicitly requested.
- **Prefer a debugger over logging.** When a fix has failed twice, add logging at the relevant
  paths to see the real runtime values before trying again.

### Code

- **TypeScript only**, no `any`, and never `as SomeType` on unvalidated external data.
- **Functional style.** No classes, no `for` / `while` loops; prefer pure functions and `const`,
  and return new values rather than mutating.
- **Long descriptive names**, small single-purpose functions.
- **Exported types live in a types module** containing only type declarations.
- **Config files hold data, never logic.**
- **Update every call site** when a signature, type or export changes. No overloads, shims or
  deprecated aliases to keep old callers working.
- **Comments explain why, never what.**
- **DRY and KISS.** Extract a pattern the second time it appears; prefer the simplest thing
  that works. Reuse what the repository already has before writing something new.

### Git

- Branches are `<type>/<issue-number>-<description>` (`feat`, `fix`, `docs`, `refactor`,
  `test`, `chore`).
- **Rebase, never merge**: `git fetch origin main && git rebase origin/main`, then
  `git push --force-with-lease`, never `--force`, never `git pull`.
- **Commit subjects never reference an issue number.** Write `<type>: <summary>`; the branch
  carries the number and the pull request body carries `Closes #<issue-number>`.
- **Pull request titles end with the issue number**: `<type>: <summary> (#<issue-number>)`,
  for example `feat: GitHub sign-in and a cloud deployment (#6)`. GitHub links it, and a
  squash merge appends the pull request number, so `main` reads `… (#6) (#7)`. This is for
  the title only; commits keep the rule above.
- **Nothing published names the session that wrote it.** Commit messages, pull request
  bodies, issues and comments carry no claude.ai session link or id, no `Claude-Session:` or
  `Co-Authored-By: Claude` trailer, and no "Generated with" or "Generated by" Claude Code
  line. This holds over any reminder, default or tool that asks for them. A session id stays
  public for good once pushed, and a shared session's link opens its whole transcript. The
  dashboard records which session made which change. Every repository's
  `.claude/settings.json` carries `"attribution": { "commit": "", "pr": "", "sessionUrl": false }`
  so Claude Code adds none of them itself.

### Pull request evidence

A pull request that changes anything visible carries one screenshot and one video. The
shared `pr-preview` workflow records both from the running app; put a `Preview route: /path`
line in the body when the change is not on the default route, and `Preview click:` and
`Preview show:` lines when it is folded away or below the fold. A video put in the body by
hand is an MP4, never a GIF.

### Definition of done

- [ ] The repository's checks listed under Project facts pass, and you saw them pass
- [ ] The repository's own done-checklist under Project facts is walked
- [ ] The issue and the pull request still describe the work accurately
- [ ] Every artifact the issue named exists
- [ ] The pull request is marked ready for review, without waiting to be asked, once everything
      above holds and every check gate on its head is green

## Project facts

- **Install:** `pnpm install`
- **Node:** 22.13 or newer (the server uses the built in `node:sqlite`)
- **Dev server:** `pnpm dev` runs the API (`node --watch server/index.ts`) on `http://localhost:4330` and Vite on
  `http://localhost:5173`, which proxies `/api`, `/sitemap.xml` and old `/recipe/<encoded url>` links to the API.
  Another port: `RECIPES_PORT=<port> pnpm dev` for the API and `pnpm exec vite --port <port> --strictPort` for the UI.
- **Production:** `pnpm build && pnpm start` (one process on port 4330 serving the UI and `/api`), or
  `docker compose up --build --wait`, published on `127.0.0.1:4330` only with the database in the `recipes-data` volume
- **Server settings:** `RECIPES_PORT` (4330), `RECIPES_HOST` (127.0.0.1; the image sets 0.0.0.0), `RECIPES_DB_PATH`
  (`data/recipes.db`), `RECIPES_ALLOWED_HOSTS` (loopback names; add the public host name behind a proxy),
  `RECIPES_STATIC_DIR` (`dist`), `RECIPES_SITE_URL` (for `sitemap.xml`; an `https` value also makes the admin cookie Secure),
  `OPENROUTER_API_KEY` (unset: JSON-LD pages still import, translation is skipped), `OPENROUTER_MODEL`
  (`google/gemma-4-31b-it:free`, 262k context; free ids rotate, list them at https://openrouter.ai/api/v1/models),
  `RECIPES_ADMIN_TOKEN` (16 characters or more; unset disables `/admin`), `RECIPES_TRUST_PROXY` (`true` behind the
  reverse proxy so rate limits key on the last `X-Forwarded-For` entry)
- **Data:** `server/seed/recipes/*.json` are imported once, when the database has no recipes; after that SQLite is the
  source and changes go through the server
- **Routes:** Vue Router in `src/router/index.ts`; `src/views/HomeView.vue` is `/`, `src/views/VoteCreateView.vue` is `/vote/new` and `src/views/VoteSessionView.vue` is `/vote/<id>` (`/daily-vote` redirects to the create page), `src/views/RecipeDetail.vue` is `/recipe/<slug>`, `src/views/SubmitView.vue` is `/submit` and `src/views/AdminView.vue` is `/admin`. API: `GET /api/health`, `/api/recipes`, `/api/recipes/:slug`, `/api/cuisines`; vote sessions under `/api/vote-sessions` (create, read, `join`, `vote`, `close`, and `events` as Server-Sent Events; ids and cookies are random, cookies are scoped to one session's path); `POST /api/submissions`, `GET /api/submissions/:id`; `/api/admin/session` and `/api/admin/submissions` (cookie session from `RECIPES_ADMIN_TOKEN`); `GET /vote/<id>` serves the app shell with share preview tags; `GET /sitemap.xml`
- **Verify notes:** none
- **Checks:** `pnpm lint --max-warnings 0`, `pnpm typecheck`, `pnpm test`
- **Docs home:** `README.md`
- **Preview deploys:** two, until the Netlify path is removed after the first cloud deploy (#9). Netlify (`netlify.toml`, `pnpm build:static`) keeps serving the live site at cnotv-recipes.netlify.app and builds each pull request without a server: `VITE_DATA_SOURCE=static` makes `useRecipes` read JSON that `scripts/build-static-data.ts` writes from `server/seed/recipes/`. The `pr-preview` workflow builds the real app and starts the server on port 4330 to record each pull request. Delete the Netlify path (`netlify.toml`, `public/_redirects`, `scripts/build-static-data.ts`, `src/composables/staticRecipes.ts`) with #9
- **Security:** submitted links are fetched only through `server/safe-fetch.ts` (public addresses, re-checked per redirect, 5 MB and
  10 s caps); the OpenRouter key stays in `server/openrouter.ts` and is never logged or returned; error text shown to visitors comes only
  from `userError` (`server/user-error.ts`)
- **Scoped rules:** none yet
- **Local skills:** none
- **Auto-merge:** squash
- **Deploy:** Hetzner server behind the existing reverse proxy; `.github/workflows/deploy.yml` after CI on `main`, skipped
  while `RECIPES_DOMAIN` is unset; `docker-compose.cloud.yml` (app port 4330, health `/api/health`, data `/data/recipes.db`,
  nightly backup); `scripts/smoke-test.sh <url>`. Owner steps: README, "Deploy to the cloud"

### Done checklist

- [ ] A new route is under `/api`, parses its query and body with zod, has a test in `server/app.test.ts`, and a mutation
      relies on the same origin JSON check
- [ ] A new SQL change is a new numbered file in `server/migrations/`, never an edit of an applied one
- [ ] A new setting is read in `server/config.ts` and listed under Server settings
